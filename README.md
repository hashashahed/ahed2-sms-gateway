# بوابة الرسائل (SMS Gateway)

ابعت رسائل SMS من شريحة جوالك الأندرويد عن طريق API بسيط، زي فكرة textbee.

```
برنامجك ──HTTP──▶ السيرفر ──WebSocket──▶ تطبيق الأندرويد ──▶ SMS من شريحتك
                    ▲                         │
                    └──── حالة الرسالة + الرسائل الواردة ◀┘
```

- **server/**: سيرفر Node.js خفيف (اعتماد واحد بس: `ws`) مع قاعدة بيانات SQLite مدمجة ولوحة تحكم.
- **android/**: تطبيق Kotlin صغير بيضل متصل بالسيرفر وبيبعت الرسائل.

---

## 1. شغّل السيرفر

بدك Node.js نسخة 22.13 أو أحدث.

```bash
cd server
npm install
npm start
```

أول مرة بيطبع **مفتاح الإدارة** (admin key) في السجل. احفظه، بتدخل فيه على لوحة التحكم.
لتختار مفتاحك بنفسك: `ADMIN_KEY=كلمة-سر-قوية npm start`

افتح `http://عنوان-السيرفر:3000` في المتصفح.

**إعدادات اختيارية (متغيرات بيئة):**

| المتغير | الوظيفة |
|---|---|
| `PORT` | المنفذ (الافتراضي 3000) |
| `ADMIN_KEY` | مفتاح لوحة التحكم |
| `DATA_DIR` | مكان قاعدة البيانات (الافتراضي `server/data`) |
| `WEBHOOK_URL` | رابط بيوصله POST لما تتغير حالة رسالة أو توصل رسالة جديدة |

**بـ Docker:**
```bash
cd server
docker build -t sms-gateway .
docker run -d -p 3000:3000 -v smsgw-data:/data -e ADMIN_KEY=كلمة-سر sms-gateway
```

> للتجربة على نفس الشبكة بتقدر تستخدم `http://192.168.x.x:3000`. للاستخدام الحقيقي حطه على VPS ورا HTTPS (مثلاً Caddy أو Nginx).

## 2. ابني التطبيق (APK)

**الطريقة الأسهل، بدون ما تنزّل إشي (GitHub Actions):**
1. ارفع المجلد كله على مستودع GitHub جديد.
2. روح على تبويب **Actions**، رح تلاقي **Build APK** شغّال لحاله (أو اضغط **Run workflow**).
3. بعد 3 إلى 5 دقائق، افتح الـ run ونزّل `sms-gateway-apk` من أسفل الصفحة. جوّاه ملف `sms-gateway.apk`.

**أو بـ Android Studio:** افتح مجلد `android` واضغط Build ▸ Build APK(s).

## 3. اربط الجوال

1. نزّل الـ APK على الجوال (رح يطلب السماح بالتثبيت من مصادر غير معروفة).
2. من لوحة التحكم اضغط **ربط جهاز**، بيطلعلك كود QR.
3. امسح الكود بكاميرا الجوال واضغط **افتح التطبيق واربط**، أو انسخ الرابط والصقه في التطبيق.
4. وافق على الصلاحيات، واضغط **استثناء التطبيق من توفير البطارية**.
5. لما يصير "متصل ✓" بتقدر تبعت.

## 4. استخدم الـ API

من لوحة التحكم أنشئ **مفتاح API**، وبعدين:

```bash
curl -X POST https://your-server.com/api/v1/sms/send \
  -H "x-api-key: sk_..." \
  -H "content-type: application/json" \
  -d '{"to": "+970599000000", "message": "مرحبا"}'
```

الرد:
```json
{ "deviceId": "...", "deviceOnline": true,
  "messages": [{ "id": "AbC123...", "phone": "+970599000000", "status": "dispatched", ... }] }
```

| Endpoint | الوظيفة |
|---|---|
| `POST /api/v1/sms/send` | إرسال. الحقول: `to` (رقم أو مصفوفة لغاية 100)، `message`، واختياري `deviceId` و `simSlot` (0 أو 1) |
| `GET /api/v1/sms/:id` | حالة رسالة |
| `GET /api/v1/sms?direction=in\|out&limit=50` | قائمة الرسائل (الواردة والصادرة) |
| `GET /api/v1/devices` | الأجهزة وإذا متصلة |

**حالات الرسالة:** `queued` (الجهاز مش متصل، بتستنى) ← `dispatched` (انبعتت للجهاز) ← `accepted` (الجهاز استلمها) ← `sent` (انبعتت من الشريحة) ← `delivered` (وصلت للمستلم). أو `failed` مع سبب الخطأ في `error`.

إذا الجهاز مش متصل، الرسالة بتنحفظ وبتنبعت أول ما يرجع يتصل. والجهاز ما بيبعت نفس الرسالة مرتين حتى لو انقطع النت بالنص.

**Webhook:** إذا حطيت `WEBHOOK_URL`، السيرفر بيبعتله:
```json
{ "event": "sms.status" | "sms.received", "data": { ...الرسالة }, "ts": 1761379200000 }
```

## ملاحظات مهمة

- **حد أندرويد:** أندرويد بيسمح افتراضياً بحوالي 30 رسالة كل 30 دقيقة لكل تطبيق، وبعدها بيطلع نافذة تأكيد. إذا بدك أكثر، وصّل الجوال بالكمبيوتر وشغّل:
  ```bash
  adb shell settings put global sms_outgoing_check_max_count 1000
  adb shell settings put global sms_outgoing_check_interval_ms 60000
  ```
- التطبيق بيستنى ثانيتين بين كل رسالة والثانية عشان ما تنحسب الشريحة سبام.
- بعض الجوالات (شاومي، هواوي، سامسونج) بتسكّر التطبيقات بالخلفية. فعّل "التشغيل التلقائي" للتطبيق وشيله من توفير البطارية.
- خلي الجوال على الشاحن والنت شغال طول الوقت.
- استخدمه للرسائل اللي الناس متوقعينها (تأكيد طلبات، رموز تحقق، تذكيرات). الرسائل الجماعية الدعائية ممكن تخلي شركة الاتصالات توقف الشريحة.
